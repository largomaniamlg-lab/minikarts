# Web30 — sala social y dragón experimental

Adds the existing A/B social candidate and an optional visual vehicle. Every existing character keeps the usual vehicle. Before joining a room or starting an offline race, choose **Coche habitual** or **Dragón — en pruebas**. Character and vehicle are independent and saved with stable identifiers. The preview renders the actual game model.

The latest local Blender source `kart_dragon_v2.blend` (iteration 13/13e) is preserved, SHA-256 `3d72fdb7f2e76279637312b96dde7ed7f27df566228e9bb544f815dc60b0edd2`. The separate game export uses uniform scale 0.5, mesh reduction and four independent wheel pivots. No silhouette redesign or nonuniform deformation. 34,589 triangles, 5 mesh objects; dimensions approximately 1.10 × 2.65 × 0.97 m. Game GLB SHA-256 `770f32872586e9bcb68f765344ebfc078d0d8380e68362c90353759fd2ee96e3`.

Vehicle selection only changes rendering and pilot placement. The CharacterBody collision, speed, acceleration, steering, jumps, shots and race authority are unchanged. The visual head/tail can extend past the existing physical collision; this is an experimental appearance, not a different hitbox. Pilot body placement and exact artistic likeness remain provisional. No new human 3D character. Uritron is excluded because the sticker is unavailable.

The server resolves the optional `vehicle` field to `habitual` or `dragon_experimental_v1`, fixes it at join, publishes it with `vehicle_version=1`, and defaults unknown/missing values to the usual vehicle. Older clients ignore the added fields and show the usual vehicle; reload the new web to see the dragon. A new client connected to an older server displays the usual vehicle and explains the fallback. Older binary graphical compatibility is not fully certified: Web29 has a previously documented shader issue.

Validated locally: 71 native vehicle checks; 14 real WebSocket vehicle/server checks; 35 social checks; 17 checks with two Chrome clients on the real web export, including different rendered vehicles, bots, ready, chat, reactions and racing. Existing regression suites completed for controls, motion, offline racing, circuits, tournaments, menus, boost and toon; 16 bots finished four circuits. New vehicle does not alter the physics calculation. Desktop render measurements are not phone performance evidence. Android/Safari physical checks remain pending.

The client-only motion index replaces repeated linear racer searches. Synthetic motion samples keep the same paths and correction bounds; the 57 existing motion checks pass. Public RTT sample was partial (19 responses, median 258 ms, p95 369 ms from the Windows host). This optimization does not reduce Internet RTT or change the wire protocol.
